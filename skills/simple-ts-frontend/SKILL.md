# Simple TypeScript Frontend

If a `ts-house-style` skill is available, read it for the shared conventions
(ESM, Biome, workspace layout, git). If not, this skill stands on its own.

For a client that must also run on iOS/Android, use the `expo-frontend` skill
instead if it is available — the two diverge enough that mixing them causes
problems.

## Loadout

| Concern | Choice |
| --- | --- |
| Build | Vite 7 |
| UI | React 19 |
| Routing | TanStack Router, file-based, `@tanstack/router-plugin` |
| Data | Apollo Client, `dataMasking: true` |
| Styling | Tailwind + shadcn/ui (Radix under it) |
| Forms | TanStack Form + zod |
| Icons | `lucide-react` |
| Charts | Recharts |
| Toasts | `sonner` |
| Tests | Vitest + Testing Library + jsdom |

## Structure

```
src/
  main.tsx            providers + RouterProvider
  routes/             file-based; __root.tsx is the shell
  components/
    ui/               shadcn primitives — no app logic, ever
    layouts/          structural wrappers
    domain/<entity>/  form.tsx + list.tsx
  hooks/
  lib/                utils.ts (cn), cache.ts
  __generated__/      gitignored, never edited
  routeTree.gen.ts    generated, committed, never edited
```

Three component layers with one hard boundary: **`components/ui/` holds no
application logic.** Those files are regenerated by the shadcn CLI; anything
added to them is lost. Compose them in `components/domain/`.

→ **[`references/folder-structure.md`](references/folder-structure.md)** — the
full tree, route file conventions, the annotated `vite.config.ts` (plugin order,
`dedupe`, the `/graphql` proxy), and the `@/` alias.

## Bootstrap

`uri: '/graphql'` — relative, always. Vite proxies it in dev; in production the
same server process serves both the bundle and the API, so there is no
`VITE_API_URL`, no CORS, and no token crossing origins.

`dataMasking: true` is the default. It makes fragment colocation an enforced
boundary rather than a convention, and it requires `useFragment` in every
consuming component.

→ **[`references/apollo-setup.md`](references/apollo-setup.md)** — the minimal
client, then the full one with auth on both transports, `ErrorLink` branching on
`extensions.code`, the WS split link, and the `typePolicies` rule for computed
views (`keyFields: false`).

## Data

Always the generated `graphql()` helper against a **literal** document — never
`gql`, never an interpolated string. Operations are colocated: queries in the
route file, fragments in the component that reads them, no `queries/` directory.

Fragments are named `<Type>_<Consumer>`, the prop type is
`FragmentType<typeof FRAGMENT>`, and `complete` from `useFragment` must be
handled.

If a `graphql-frontend` skill is available, read it for the fragment layer in
depth — component ownership, the two kinds of masking and their two colliding
`useFragment` functions, composition, and migration. If not, the reference below
covers what this stack needs.

→ **[`references/data-fetching.md`](references/data-fetching.md)** — the
fragment pattern, loading/error/empty state conventions, why to branch on `data`
before `loading` under `cache-and-network`, and the `@0no-co/graphqlsp` plugin.

## Cache invalidation

Apollo normalization already patches every view of an entity a mutation
returns. Only two things need help: a list gaining or losing a member, and a
server-computed field going stale.

Repos differ here — smaller ones use `refetchQueries`, larger ones evict root
fields by name. **Follow the repo; do not mix.** The eviction approach exists
because naming *queries* couples a mutation to whichever pages existed when it
was written, and a page added later silently shows stale data.

→ **[`references/cache-invalidation.md`](references/cache-invalidation.md)** —
`ROOT_FIELDS` / `DERIVED` / `invalidate` / `appendToField` / `evictEntity` in
full, a decision table, and the single-subscriber live-updates pattern.

## Layout components

Structural wrappers own spacing, alignment, and scroll; pages own content.
**Reach for a layout component rather than hand-rolling
`<div className="flex items-center justify-between">` inline** — uniformity
across list pages, and a spacing change becomes a single edit.

The one bug worth memorizing: a scrolling flex child needs `min-h-0`, or
`overflow-y-auto` never engages and the whole page scrolls instead.

→ **[`references/layout-components.md`](references/layout-components.md)** —
`ListLayout`, `FormListLayout`, the app shell and nav array, the add-button
placement rule for detail-page sections, and how to write a new one.

## Forms

TanStack Form + zod, field components bound once through `createFormHook`. The
form takes `onSubmit: (value) => Promise<void>` and `onCancel` — **it never calls
the mutation itself**, so one form serves a page, a dialog, and a test.

Validate on submit, not on change. `form.Subscribe` around the submit button.
Reset only on success. Server errors render in the form, not in a toast.

→ **[`references/forms.md`](references/forms.md)** — the shared field context,
a complete form, the rules with their reasons, and the dialog pattern.

## Dark mode

Tailwind `darkMode: 'class'`, tokens as CSS variables in `index.css` under
`:root` and `.dark`. Components reference tokens (`bg-background`,
`text-muted-foreground`), never raw colors — a literal `bg-white` is a dark-mode
bug by construction. A `use-dark-mode` hook toggles the class on `<html>` and
persists the choice.

## After changing anything

```bash
npm run codegen && npm run check && npm test
```

Codegen first — a stale `__generated__/` makes `typecheck` report errors that do
not exist.
