# Folder structure

```
app/                          the client workspace
├── index.html
├── vite.config.ts
├── tsconfig.json
├── components.json           shadcn/ui config
├── package.json
└── src/
    ├── main.tsx              bootstrap: providers + RouterProvider
    ├── index.css             tailwind + design tokens
    ├── routeTree.gen.ts      generated by @tanstack/router-plugin — never edit
    ├── __generated__/        generated by graphql-codegen — never edit
    │   ├── gql.ts            the typed `graphql()` helper
    │   ├── graphql.ts        every operation/fragment type
    │   └── index.ts
    ├── routes/
    │   ├── __root.tsx        shell: nav + <Outlet />
    │   ├── index.tsx         /
    │   ├── persons/
    │   │   ├── index.tsx     /persons
    │   │   └── $id.tsx       /persons/:id
    │   └── labels/index.tsx  /labels
    ├── components/
    │   ├── ui/               shadcn primitives — no app logic
    │   ├── layouts/          structural wrappers
    │   └── domain/
    │       ├── person/
    │       │   ├── form.tsx
    │       │   └── list.tsx
    │       └── label/
    │           ├── form.tsx
    │           └── list.tsx
    ├── hooks/
    └── lib/
        ├── utils.ts          cn()
        └── cache.ts          invalidation helpers
```

## The three component layers

| Layer | Location | Purpose |
| --- | --- | --- |
| **UI primitives** | `components/ui/` | shadcn/ui components — no app logic |
| **Domain components** | `components/domain/` | feature-specific forms and lists |
| **Layouts** | `components/layouts/` | structural page wrappers |

**The boundary rule: never put application logic in `components/ui/`.** Those
files are generated by the shadcn CLI and are re-generatable; anything added to
them is lost on the next `npx shadcn@latest add`. Compose them in
`components/domain/` instead.

A domain directory is always `<entity>/form.tsx` + `<entity>/list.tsx`. The form
owns validation, the list owns the fragment.

## Routes

File-based, via `@tanstack/router-plugin/vite`. The plugin watches
`src/routes/` and regenerates `routeTree.gen.ts` during `npm run dev`.

- `routes/persons/index.tsx` → `/persons`
- `routes/persons/$id.tsx` → `/persons/:id`
- `routes/persons/$id/_layout.tsx` → a nested layout for that subtree
- `routes/__root.tsx` → the shell every route renders inside

```tsx
export const Route = createFileRoute('/persons/$id')({
  component: PersonDetail,
});
```

**`routeTree.gen.ts` is generated. Never edit it, never resolve merge conflicts
in it — regenerate.**

A route file owns: its GraphQL operations, its page-level state (including
dialog open/close), and the composition of domain components. It does not own
markup that a layout component could own.

## `vite.config.ts`

```typescript
import { fileURLToPath } from 'node:url';
import tailwindcss from '@tailwindcss/vite';
import { tanstackRouter } from '@tanstack/router-plugin/vite';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    tanstackRouter({ target: 'react', autoCodeSplitting: true }),
    react(),
    tailwindcss(),
  ],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
    // The workspace root may hoist a second react copy for another app, and
    // radix or recharts can end up importing it — which makes every hook call
    // throw. One copy, always.
    dedupe: ['react', 'react-dom'],
  },
  server: {
    // Listen on all interfaces — dev often runs on a VM or remote docker host,
    // where vite's localhost-only default would be unreachable.
    host: true,
    port: 3000,
    proxy: {
      '/graphql': process.env.SERVER_URL ?? 'http://localhost:3001',
    },
  },
});
```

Three things here are load-bearing:

- **`tanstackRouter` comes before `react()`.** The router plugin transforms route
  files; running after the React plugin means it never sees them.
- **`dedupe: ['react', 'react-dom']`** in any monorepo where another workspace
  pins a different React. Two copies is the classic "Invalid hook call" source.
- **The `/graphql` proxy** keeps the client on a relative URL in dev, so tokens
  never cross origins and the production build (which is served by the same
  Express process) needs no environment variable at all.

## Path alias

`@/` → `src/`. Declared in both `vite.config.ts` (`resolve.alias`) and
`tsconfig.json` (`compilerOptions.paths`) — both, or the editor and the bundler
disagree.

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
```

Never `../../components/ui/button`. Always `@/components/ui/button`.

## Generated files

| Path | Produced by | Rule |
| --- | --- | --- |
| `src/routeTree.gen.ts` | `@tanstack/router-plugin` during `dev`/`build` | committed, never edited |
| `src/__generated__/` | `npm run codegen` | gitignored, never edited |

Both are excluded from Biome. If `typecheck` reports errors in code you did not
touch, run codegen before reading them.
